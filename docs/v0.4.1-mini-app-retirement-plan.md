# v0.4.1 — retiring the Mini App

**Status: step 3 is DONE (v0.4.6). Steps 4-6 are still a plan.**

Written after v0.4.0 moved every user-facing form into the bot (ADR-0017). This
records what retirement actually costs, which turned out to be more than a
config change and less than a rewrite.

## What v0.4.6 actually did to §2

**Every open-app button is gone, including the six §2 marked «Blocked».** That
was a product call and it overrides the recommendation below: the button was
under *almost every message the bot sends*, so the one place it was the real next
step read like the twenty places it was not — and `reply_markup` holds one thing,
so it was also what kept the persistent menu off nearly every message.

The five screens §3 names still have no bot equivalent. Removing their buttons
did not change that; it changed who is asked to notice. `/discover` is still
city-only, the coin ledger still has no bot command, and writing a review still
has no bot flow. **§3's recommendation stands and is now the outstanding work** —
it is just no longer gated on the buttons.

What did *not* change:

- **`deepLink` survives on every template.** Only the button went. §6 asked for
  an assertion that removed templates emit no `deepLink`; the opposite choice was
  made deliberately, because `deep-links.test.ts` checking every target against
  the allowlist is worth more than an assertion that a field is absent, and it is
  what caught the two templates in §2b pointing at a route that never existed.
- **The channel post keeps its button** (§2c). It is read by people who have not
  started the bot, and it is the only action on the post. The "repoint to
  `?start=`" item is still open.
- **nginx is untouched.** The Mini App is still served, which is what makes this
  step revertible by a deploy.

---

## 1. What retirement is not

**It is not removing a compose service or a server block.**
`docker/sites-available/app.paayatam.online.conf` is a single `server` block that
serves the Mini App bundle **and** the API, the Telegram webhook and the health
endpoint. Deleting it takes the bot offline.

**It is not just nginx.** Twenty-three notification surfaces render a button that
opens the Mini App. Stop serving it and every one of them lands on a 404 — a
button the product itself put in front of the user.

`apps/admin` is a **different vhost** (`admin.paayatam.online`) with its own
root, and is not affected by anything here. ADR-0003 continues to govern it.

## 3. The six that block full retirement

Five templates point at screens with **no bot equivalent**. Each needs a bot
surface before its button can go:

| Screen | Needed | Size |
|---|---|---|
| `ReviewsView` (writing) | A review wizard: rating → tags → optional comment | one wizard, ~3 steps |
| `ReviewsView` (reading) | `/reviews` extended to show revealed reviews received | a formatter |
| `WalletView` | `/wallet` — the coin ledger, paged like a digest | a formatter |
| `DiscoverView` (filters) | Either accept that `/discover` is city-only, or add a filter wizard | a decision, then possibly a wizard |
| `EventDetailView` | `/event <id>` or a deep-linked detail message | a formatter |

**Recommendation: do the first three.** They are formatters and one small wizard,
and they are what turns «باز کردن برنامه» from a necessity into a courtesy.
Leave `DiscoverView`'s filters in the app and accept that discovery is
"the common case in the bot, everything in the app" — the same boundary
`/discover` already documents.

That last point means **the Mini App is not fully retired in v0.4.1** unless the
filter question is answered. See §7.

## 4. The nginx surgery

`docker/sites-available/app.paayatam.online.conf`.

**Remove** — the four static-serving directives:

| Line | Directive | Why |
|---|---|---|
| 52 | `root /srv/www/miniapp;` | the bundle's location on disk |
| 53 | `index index.html;` | the SPA entry point |
| 157 | `location /assets/ { … try_files $uri =404; }` | hashed bundle assets |
| 166 | `location = /index.html { … }` | the SPA document |
| (below 166) | the `location /` SPA fallback | rewrites every unknown path to `index.html` |

**Keep, untouched** — every proxy location:

| Line | Location | Why |
|---|---|---|
| 20 | `/.well-known/acme-challenge/` | certbot renewal; removing it breaks TLS at the next renewal |
| 65 | `= /metrics` | closed from the internet, unchanged |
| 73 | `= /ready` | health |
| 85 | `/api/v1/auth/` | **still needed** — the admin panel and any future client authenticate here |
| 107 | `= /api/v1/catalog` | exact-match, deliberately narrow |
| 115 | `/api/` | the API |
| 134 | `/telegram/webhook/` | **the bot.** Removing this is the outage |
| 145 | `= /health` | the deploy's own verification target |

**Replace** the SPA fallback with a redirect to the bot:

```nginx
# Was: try_files $uri $uri/ /index.html;
location / {
    return 302 https://t.me/$PAYETAM_BOT_USERNAME;
}
```

Somebody following an old link lands in the bot rather than on a 404. This also
covers the deep links in §2 that are missed — which is the argument for doing the
nginx step **last**.

The `web` Docker target still builds and copies the bundle. Leave it: an image
that carries an unserved directory costs nothing, and rolling back is then a
one-line nginx change rather than a rebuild.

## 5. Order, and the rollback at each step

Each step is independently deployable and independently reversible.

| # | Step | Rollback |
|---|---|---|
| 1 | Ship v0.4.0 as it stands, Mini App still served | `rollback.sh`, or `ENABLE_CONVERSATION_WIZARD=0` |
| 2 | Add `/wallet`, extend `/reviews`, add the review wizard | revert the commit; the buttons are untouched |
| 3 | Remove the 15 «Remove» deep links in §2 | revert; the buttons come back with the deploy |
| 4 | Repoint the channel post to `?start=` | revert |
| 5 | nginx: drop the five static directives, add the 302 | **one-line revert** — restore `root`/`index` and the fallback, `nginx -s reload`. No rebuild |
| 6 | After a quiet month: stop building the `web` bundle | revert the Dockerfile |

Step 5 is the only one users see immediately, and it is the cheapest to undo.
That ordering is deliberate: the expensive, slow-to-revert work happens while the
app is still there to fall back to.

## 6. Verification at each step

- After 3: `deep-links.test.ts` still passes — it asserts every template's target
  is on the allowlist, and a **removed** button trivially satisfies it. Add an
  assertion that the removed templates emit *no* `deepLink`, or the test will not
  notice a re-introduction.
- After 5: `curl -I https://app.paayatam.online/` returns 302 to the bot;
  `curl https://app.paayatam.online/health` still returns 200;
  `./scripts/set-webhook.sh --info` still reports no delivery errors;
  `./scripts/smoke-tests.sh` passes.
- Throughout: `pnpm bot-walkthrough` renders every screen, so a removed button is
  visible in a diff of its output.

## 7. The open question

**Is `/discover` without filters an acceptable replacement for `DiscoverView`?**

If yes, v0.4.1 can retire the Mini App entirely and the answer is §4's 302.

If no, the Mini App keeps one screen and the retirement is partial — which means
the vhost keeps serving `/assets/` and a narrowed `location`, and the 302 applies
only to paths outside `/discover`. That is a materially different nginx change,
which is why this document does not pick.

This is a product decision, not an engineering one.
